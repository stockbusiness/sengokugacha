# 千ノ国パスポート LINE新規登録・紹介試験結果(§5.6、部分実施)

区分: 1.ソースコード確認済み / 2.local確認済み / **3.staging確認済み(既存アカウント範囲のみ)** / 4.production未確認 / **5.未対応(新規登録・紹介確定の実データ試験)** / 6.問題あり / 7.管理者操作待ち / 8.Stripeアカウント待ち

Stripe取得待ち期間対応指示書§5.6に基づき、2026-07-28に実機テストを試みた。ただし`stockbusiness`側に未登録のテスト用LINEアカウントが用意できなかったため、**新規登録・紹介確定(referral capture/confirm、sengoku-ai.comとの実接続を含む)の実データ試験は今回未実施**。代わりに、当日実施した一連のPR-A/B/Cマージ後の回帰確認として、既存アカウントでのLIFFログイン正常性のみ確認した。

## 実施内容と結果

### 実施1: 既存アカウントでのLIFFアプリ動作確認

`stockbusiness`が実機(LINEアプリ内)から戦国パスポートを開き、スクリーンショットで動作を確認。

- 国家ランキング画面が実データ(ユーザー名・ポイント)で正しく表示された
- 下部ナビゲーション(パスポート/武将登用/図鑑/地図/購入)が全て表示され、機能している様子
- エラー画面・白画面等の異常は見られなかった

**結論**: 当日マージしたPR-A(セキュリティ修正)・PR-B(common_user_id再解決機能等)・PR-C(Outbox/reconciliation)がLIFFログイン・既存ユーザーの基本機能に回帰を起こしていないことを確認できた。

### 未実施: 新規登録・紹介確定の実データ試験

以下は次回、テスト用LINEアカウント(サブアカウント等)が用意できた際に実施する。

1. 代理店(`agents`テーブル)から`referral_code`付きの紹介リンク(`?ref=AGENT_CODE`)を取得
2. 未登録のLINEアカウントで紹介リンク経由でLIFFを開き、新規登録を完了する
3. 管理画面`/admin/users`で新規ユーザーの`referring_agent_id`が正しい代理店を指しているか確認
4. `src/lib/passport.ts`の`syncCommonUserHub()`が呼ぶsengoku-ai.com側の`referrals/confirm`・`common-users/resolve`が実際に成功するか(外部システム側の応答を含む)を確認
5. `common_user_id`が正しく解決されるか、解決できない場合は`common_user_resolution_attempts`に記録され、§5.7で実装した再解決UIから手動再解決できるかを確認

## 今後の対応

- Stripeアカウント取得後、決済試験(§7)を行う際にテスト用LINEアカウントも同時に用意し、本ドキュメントの「未実施」項目を合わせて実施することを推奨する。
- それまでは区分5(未対応)のまま`docs/PHASE_C1_PRE_STRIPE_COMPLETION_REPORT.md`(§204)に引き継ぐ。
