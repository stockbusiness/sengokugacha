# PR-P1b 実装計画 — 旧報酬管理画面の清算専用化

- 作成日: 2026-08-20
- 対象: `stockbusiness/sengokugacha`（Passport）
- 準拠: `01_PASSPORT_IMPLEMENTATION_INSTRUCTIONS_20260820.md` PR-P1「停止中は管理画面を履歴参照専用にし、『Agencyへ移管済み／新規計上停止中』を表示する」
- 起点: `main` = `5cb21b1`（PR-P1a マージ済み）
- 本計画の承認を受けるまで、コード変更は開始しません。

## 1. 目的

PR-P1a で**サーバ側の書込みは既に止まっています**。本PRはその状態を**画面に正しく反映**するものです。目的は運用表示ひとつに限定します（実行ルール §4）。

現状、管理者から見ると次のようになっています。

- 報酬ルール画面に作成フォームと編集・削除・公開ボタンが**そのまま出ている**
- 押すと 409 のエラーメッセージが返る
- **なぜ止まっているのかは、押してみるまで分からない**

「操作できるように見えるが実は止まっている」状態を解消します。

## 2. 対象画面と扱い

停止対象と継続対象が混在しているため、画面ごとに扱いを変えます。**全部を一律で「参照専用」にすると、継続すべき清算業務まで止まって見えます。**

| 画面 | パス | サーバ側の状態 | 本PRでの表示 |
|---|---|---|---|
| 土地販売報酬ルール | `/admin/castle-commission-rules` | **書込み停止**（409） | 作成フォームと編集・削除・公開ボタンを**隠す**。参照専用にして移管バナーを出す |
| 土地販売報酬元帳 | `/admin/castle-commissions` | 確定操作は**継続可** | 一覧・確定操作は維持。**新規計上が止まっている旨**のバナーを出す |
| 土地報酬の支払処理 | `/admin/castle-payouts` | 支払処理は**継続可** | 一覧・支払操作は維持。同上のバナー |
| 売上ログ | `/admin/agent-sales` | 停止対象外（Q4） | **変更しない** |

### 2.1 バナーの文言

移管の事実と、いま何ができるのかを1箇所で伝えます。

**報酬ルール画面（書込み停止中）**

> **Agencyへ移管済み — 新規計上停止中**
> 報酬の計算・支払はAgencyが正本を持ちます。Passport側での報酬ルールの作成・編集・削除・公開は停止しています。過去のルールは参照のみ可能です。

**元帳・支払画面（清算のみ可能）**

> **Agencyへ移管済み — 新規計上停止中**
> 新しい報酬は計上されません。この画面では、停止前に計上済みの報酬の確定・支払（清算）のみ行えます。

### 2.2 対象が0件であることについて

本番は `commission_rule_sets` も `commission_ledger` も **0件**です。したがって実際の見え方は「**空の一覧＋移管バナー**」になります。

表示自体は指示書の要求であり、また将来データが入ったときに正しく振る舞う必要があるため実装しますが、**現時点で清算すべき対象は存在しません**。この点をご承知おきください（§8 確認事項1）。

## 3. 設計

### 3.1 画面へ状態を渡すAPI

管理画面はクライアントコンポーネントで、フラグを直接読めません。参照専用のエンドポイントを1本追加します。

`GET /api/admin/commission-write-settings`

```json
{ "landSaleCommissionWriteEnabled": false, "commissionRuleSetWriteEnabled": false }
```

管理者セッション必須。**GET のみで、書込みは実装しません。** フラグの変更は運用DB操作（責任者の承認が必要）に限り、画面からは切り替えられないようにします。誤操作で報酬計上が再開する経路を作らないためです。

### 3.2 表示判定は純粋関数に置く

`src/modules/castle/domain/commission-admin-view.ts`（新規）

```
export type CommissionAdminNotice =
  | { kind: "write_disabled" }   // 書込み停止。操作UIを出さない
  | { kind: "settlement_only" }  // 清算のみ可能。操作UIは残す
  | { kind: "none" };            // 通常運用

export function describeCommissionAdminNotice(
  screen: "rule_sets" | "ledger" | "payouts",
  settings: CommissionWriteSettings
): CommissionAdminNotice
```

文言も同じモジュールに置き、3画面で表記が食い違わないようにします。vitest で全組み合わせを検証します。

### 3.3 共有バナーコンポーネント

`src/components/admin/CommissionMigrationNotice.tsx`（新規）。`CommissionAdminNotice` を受け取り、`kind: "none"` なら何も描画しません。

### 3.4 操作UIを「隠す」のか「無効化する」のか

**隠します**（報酬ルール画面の作成フォーム・編集・削除・公開ボタン）。

`disabled` にすると、押せないボタンが並んだまま理由が分からない画面になります。バナーで理由を説明したうえで**操作要素そのものを消す**方が、状態が正しく伝わります。参照に必要な一覧・料率表示はそのまま残します。

**APIは削除しません。** サーバ側のガード（PR-P1a）が正で、画面はその表示にすぎない、という関係を保ちます。画面だけ塞いでAPIが開いている状態は作りません（逆も同様で、フラグをONにすれば画面の操作UIも自動的に戻ります）。
