## 案1: 区画の相談ボタン

### やったこと

区画詳細(`/castles/[castleId]/plots/[plotId]`)に「この区画について相談する」を追加し、
既存のメタバース内覧の相談申込フォーム(`/metaverse-tour/inquiries/new`)へ `?castlePlotId=` 付きで送る。

新しいテーブルは作らず、`metaverse_inquiries` に `castle_plot_id` を1列足しただけ。
相談種別・希望連絡方法・希望日時・予算・利用目的・2つの同意チェック・対応履歴・
`new → contacted → in_progress → closed` の対応状況は既存のものをそのまま使う。

### 対応者(誰が相談を受けるか)

**紹介元代理店へ自動で割り当て、紹介元が分からないユーザーの相談は未割り当てのまま残して本部が割り振る。**

これは既存のメタバース相談申込と同じ挙動(`users.referring_agent_id` を `metaverse_inquiries.agent_id` に入れる)で、
新しい振り分けルールは作っていない。城主へ割り当てる運用にしたい場合は
`src/app/api/metaverse/inquiries/route.ts` の `agentId` の決め方を変えるだけで切り替えられる。

### 画面

- 区画詳細: 「相談を申し込む」ボタン(販売中の区画のみ)
- 相談フォーム: 冒頭に「相談する区画 / 岐阜城 / 一番区画」を表示
- 受付完了画面: 区画名を表示し、戻り先を城一覧にする
- 管理画面 `/admin/metaverse/inquiries`: 城の区画からの相談は `🏯 岐阜城 / 一番区画` と表示され、
  メタバース物件からの相談と同じ一覧に並ぶ

## 案2: 解放進捗＋LINE個別通知

### 進捗表示

城一覧で未解放の城に「あと3武将で解放(尾張の制圧)」「あと2国で解放(関東地方の制覇)」と残りを出す。

- 解放条件が「主要国の制圧」の城 → その国の必須武将のうち未獲得の数
  (必須武将の決め方は `conquest_rules` があればそれ、無ければその国の武将全部。
  `getProvinceRequiredWarlords()` と同じフォールバック)
- 解放条件が「主要国の地方コンプ」の城 → その地方の未制圧の国の数
  (地方制覇の判定と同じく、天下統一用の最終国は数に含めない)

未解放の城の**中身**(詳細・区画)は引き続き伏せる方針(実装指示書v1.0 6-6)を変えていない。
出すのは「解放までの距離」だけ。

判定は純粋関数 `src/modules/castle/domain/castle-unlock-progress.ts` にあり、単体テスト済み。

### LINE通知

ガチャで国を制圧した / 地方を制覇した瞬間に、それで解放された城をLINEで個別通知する。

```
【戦国パスポート】尾張の制圧により「犬山城」が解放されました。アプリから城の詳細と販売中の区画をご覧いただけます。
```

- 送信は `execute_gacha_draw()` のトランザクションがコミットされた後のベストエフォート
  (動画演出の選定と同じ扱い。失敗してもガチャ自体は成功させる)
- LINEのpush送信には冪等キーが無いため、`castle_unlock_notifications` の
  `unique (user_id, castle_id)` で二重送信を防ぐ。同じ城の解放通知は生涯1回だけ
- 台帳に入れてから送るので、送信に失敗した城は再送されない(通知は残高・権利・報酬に一切影響しない)

## 案3: 内覧システムと区画の接続

`castle_plots.property_id` → `metaverse_properties.id` の1本の外部キーで、
既存のメタバース内覧(3Dシーン・ホットスポット・お気に入り・閲覧ログ)を区画から再利用できるようにした。

- 管理画面 `/admin/castles/[id]` の区画一覧に「内覧」プルダウンを追加。
  選択肢は公開中(published)・準備中(coming_soon)の物件のみ
  (下書き・非表示の物件はLIFF側の内覧導線に出てこないため、紐づけても内覧ボタンが機能しない)
- 区画詳細に「内覧を見る」カードを追加。紐付けが無い区画には出ない
- 相談カードより上に置いている(「見てから相談する」の順にしたいため)
